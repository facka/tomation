# Requirements Document

## Introduction

This document specifies the requirements for the Lab Tab UX Redesign in the Tomation browser extension side panel. The redesign improves the user workflow by repositioning the AI configuration as the first step, introducing a full HTML code viewer with editing capabilities, supporting two context modes (full page HTML and inspect element), enabling multi-node selection with deduplication, and adding a privacy label to inform users about automatic data sanitization.

## Glossary

- **Lab_Tab**: The panel view in the Tomation browser extension side panel where users inspect DOM elements and generate Page Object Model (POM) files using AI.
- **AI_Config_Section**: The UI component where users configure the AI provider, model, and API key.
- **Code_Viewer**: A code editor component that displays HTML content with syntax highlighting and allows the user to review and edit the content before sending it to AI.
- **Context_Mode**: The method by which HTML content is captured for AI generation — either "Full HTML" (entire page) or "Inspect Element" (user-selected nodes).
- **Inspect_Element_Mode**: A context mode where the user visually picks specific DOM nodes from the inspected page using a click-to-select inspector.
- **Full_HTML_Mode**: A context mode that captures the entire page HTML for AI generation.
- **Selected_Nodes_List**: The ordered collection of DOM nodes the user has selected in Inspect Element mode.
- **Mini_Editor**: A compact, read-only code display showing the outerHTML of a single selected node within the Selected Nodes List.
- **Privacy_Label**: A visible UI label informing users that sensitive data is automatically stripped from HTML before sending to the AI service.
- **Inspector_Script**: The content script (inspector.js) injected into the page to enable element highlighting and click-to-select.
- **Privacy_Sanitizer**: The existing function (sanitizeHtmlForPrivacy) in the background script that strips emails, passwords, and personal information from HTML.
- **POM_File**: A Page Object Model file generated by the AI based on the provided HTML context.

## Requirements

### Requirement 1: AI Configuration Positioned First

**User Story:** As a user, I want the AI configuration section to be the first thing I see in the Lab tab, so that I can complete the prerequisite setup step before doing anything else.

#### Acceptance Criteria

1. THE Lab_Tab SHALL render the AI_Config_Section as the first (topmost) component in the panel layout, preceding InspectSection, NodePreview, GenerateSection, and CodeOutput.
2. WHEN the AI_Config_Section loads and a saved configuration exists with an API key containing at least one non-whitespace character, THE AI_Config_Section SHALL display in collapsed state showing a summary header with the selected provider name, model name, and a check mark icon.
3. WHEN the AI_Config_Section loads and no saved configuration exists or the stored API key is empty or contains only whitespace, THE AI_Config_Section SHALL display in its expanded form showing the configuration fields (provider, API key, model) prompting the user to fill in credentials.
4. WHEN the user clicks the collapsible summary header, THE AI_Config_Section SHALL toggle between the collapsed summary view and the expanded configuration form, regardless of whether a valid configuration exists.
5. WHEN the user saves a valid configuration while the AI_Config_Section is expanded, THE AI_Config_Section SHALL remain expanded and display a confirmation indicator for 2 seconds.

### Requirement 2: Full HTML Code Viewer

**User Story:** As a user, I want to see the selected HTML content in a code viewer that I can edit, so that I can review and modify the HTML before sending it to the AI.

#### Acceptance Criteria

1. THE Lab_Tab SHALL display a Code_Viewer component that shows the HTML content to be sent to AI.
2. THE Code_Viewer SHALL apply syntax highlighting to HTML content by visually distinguishing tags, attribute names, attribute values, and text content using different colors or styles.
3. THE Code_Viewer SHALL allow the user to edit the displayed HTML content directly within the component as a text-editable area.
4. WHEN the user triggers AI generation, THE Lab_Tab SHALL always use the current content displayed in the Code_Viewer as the input, regardless of whether the user has made edits.
5. WHILE the context mode is set to Full_HTML_Mode, THE Code_Viewer SHALL display the full page HTML content retrieved from the active tab.
6. WHILE the context mode is set to Inspect_Element_Mode, THE Code_Viewer SHALL display the concatenated outerHTML of all selected nodes.
7. IF no HTML content is available for display (no node selected in Inspect_Element_Mode, or page HTML retrieval fails in Full_HTML_Mode), THEN THE Code_Viewer SHALL display an empty state indicating that no content is loaded, and SHALL remain in this state until content becomes available through user action.
8. WHEN the user switches context mode, THE Code_Viewer SHALL replace its content with the HTML corresponding to the new mode, discarding any previous edits.

### Requirement 3: Two Context Modes

**User Story:** As a user, I want to choose between capturing the full page HTML or selecting specific elements, so that I can control the scope of HTML context provided to the AI.

#### Acceptance Criteria

1. THE Lab_Tab SHALL provide two mutually exclusive context mode options: "Generate with Full HTML" and "Select elements with Inspect Element".
2. WHEN the user selects "Generate with Full HTML", THE Lab_Tab SHALL retrieve the complete page HTML from the active tab and display it in the Code_Viewer.
3. WHEN the user selects "Select elements with Inspect Element", THE Lab_Tab SHALL enable the Inspector_Script for the user to visually pick DOM nodes from the page.
4. THE Lab_Tab SHALL persist the user's context mode selection in reactive state for the duration of the browser extension panel session.
5. WHEN the user changes context mode from Inspect_Element_Mode to Full_HTML_Mode, THE Lab_Tab SHALL retrieve fresh page HTML but SHALL NOT clear the Selected_Nodes_List.
6. WHEN the user changes context mode, THE Lab_Tab SHALL update the radio button selection immediately without triggering generation.

### Requirement 4: Multi-Node Selection in Inspect Element Mode

**User Story:** As a user, I want to select multiple DOM nodes when using Inspect Element mode, so that I can include several page sections in the AI generation context.

#### Acceptance Criteria

1. WHILE in Inspect_Element_Mode, THE Lab_Tab SHALL allow the user to select up to 20 DOM nodes by clicking elements on the page, keeping the inspector active between selections until the user explicitly exits Inspect_Element_Mode.
2. WHEN the user selects a node that is already in the Selected_Nodes_List (same outerHTML), THE Lab_Tab SHALL discard the duplicate and not add it again.
3. THE Lab_Tab SHALL display each selected node in a separate Mini_Editor within the Selected_Nodes_List, showing the node's outerHTML content.
4. THE Lab_Tab SHALL display a delete button on each Mini_Editor that allows the user to remove that specific node from the Selected_Nodes_List.
5. WHEN the user clicks the delete button on a Mini_Editor, THE Lab_Tab SHALL remove that node from the Selected_Nodes_List and regenerate the Code_Viewer content by concatenating the outerHTML of the remaining nodes in their selection order.
6. WHEN the user triggers AI generation in Inspect_Element_Mode, THE Lab_Tab SHALL concatenate the outerHTML of all nodes in the Selected_Nodes_List in their selection order and send the combined HTML to the AI.
7. IF the user triggers AI generation while the Selected_Nodes_List is empty, THEN THE Lab_Tab SHALL display an error message indicating that at least one node must be selected and SHALL NOT send a request to the AI.
8. WHEN the user selects a node that would exceed the maximum of 20 nodes in the Selected_Nodes_List, THE Lab_Tab SHALL discard the selection and display a message indicating that the maximum node limit has been reached.

### Requirement 5: Privacy Label

**User Story:** As a user, I want to see a visible notice that my sensitive data is stripped from HTML before it is sent to the AI, so that I feel confident about data privacy.

#### Acceptance Criteria

1. THE Lab_Tab SHALL display a Privacy_Label as a static text element positioned near the generate button within the GenerateSection, so that it is visible whenever the generate action is visible.
2. THE Privacy_Label SHALL contain text stating that email addresses, passwords, and personally identifiable information are automatically stripped from the HTML before sending to the AI service.
3. THE Privacy_Label SHALL remain visible regardless of whether the selected context mode is "Full HTML" or "Inspect Element".
4. IF no element has been selected or no AI provider is configured, THEN THE Privacy_Label SHALL still be displayed in its designated position within the GenerateSection.

### Requirement 6: Inspector Script Multi-Select Behavior

**User Story:** As a user, I want the element inspector to remain active after selecting a node so I can continue selecting additional nodes without restarting the inspector.

#### Acceptance Criteria

1. WHILE in Inspect_Element_Mode, WHEN the user clicks a DOM element, THE Inspector_Script SHALL send the selected node data to the panel, continue listening for mousemove, click, and keydown events, and keep the highlight overlay visible on the page.
2. WHILE in Inspect_Element_Mode, WHEN the user moves the mouse over a different element after a selection, THE Inspector_Script SHALL reposition the highlight overlay to the newly hovered element.
3. WHEN the user presses the Escape key during Inspect_Element_Mode, THE Inspector_Script SHALL send an INSPECT_CANCELLED message, remove the highlight overlay from the DOM, and remove all event listeners (mousemove, click, keydown).
4. WHEN the user explicitly deactivates Inspect_Element_Mode via the panel UI, THE Inspector_Script SHALL remove the highlight overlay from the DOM and remove all event listeners (mousemove, click, keydown).
5. IF the Inspector_Script receives a REMOVE_INSPECTOR message while not in Inspect_Element_Mode, THEN THE Inspector_Script SHALL take no action.

### Requirement 7: HTML Concatenation for Generation

**User Story:** As a user, I want all my selected nodes to be combined into a single HTML context for AI generation, so that the AI can produce a POM covering all selected elements.

#### Acceptance Criteria

1. WHEN the context mode is Inspect_Element_Mode and the user triggers generation and the Selected_Nodes_List contains at least one node, THE Lab_Tab SHALL concatenate the outerHTML of each node in the Selected_Nodes_List in selection order, separated by a single newline character (\n), producing one combined HTML string.
2. WHEN the context mode is Full_HTML_Mode and the user triggers generation, THE Lab_Tab SHALL send the current content of the Code_Viewer to the AI (reflecting any edits the user has made to the originally captured full page HTML).
3. THE Lab_Tab SHALL pass the concatenated or full HTML through the Privacy_Sanitizer before sending it to the AI service, and SHALL send the sanitized output without further modification.
4. IF the context mode is Inspect_Element_Mode and the user triggers generation while the Selected_Nodes_List is empty, THEN THE Lab_Tab SHALL display an error message indicating that at least one node must be selected and SHALL NOT send a generation request to the AI service.
